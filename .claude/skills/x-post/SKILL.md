# X投稿文の作成

ユーザーが伝えたい内容から、Xの投稿文案を作る。

## 前提

このアカウントは**現役の小学校教員が、自分で作った算数ドリルサイトについて発信する**もの。
読者は主に保護者と教員。**信頼が最大の資産**であり、それを損なう文体は使わない。

運用方針の正典は `docs/x-operations.md`。**作業前に必ず 2.2 / 2.3 / 3.5 を読むこと。**
以下はその要約であり、齟齬があれば `docs/x-operations.md` が優先される。

## 手順

1. `docs/x-operations.md` の 2.2（発信者の人格）、2.3（トーン＆マナー）、3.5（投稿の型）を読む
2. ユーザーの依頼内容が、投稿の型 A / B / C のどれに当たるかを判断する
   - **A. 今日の1問** — 算数の問題を出す
   - **B. つまずき解説** — つまずく箇所の考え方、教え方のコツ
   - **C. 制作の裏側／更新報告** — 何を作っているか、なぜそう作ったか
   - どれにも当てはまらない場合は、型に無理に寄せず内容に合わせて書く
3. **文案を2〜3案作る。** 切り口を変える（例: 結論から / エピソードから / 問いかけから）
4. 各案について `count.py` で文字数を検証する（**必須**。目視で数えない）
5. 検証済みの文案を、文字数とともに提示する

## 文字数の検証

```bash
python3 .claude/skills/x-post/count.py 案.txt          # 投稿（上限280）
python3 .claude/skills/x-post/count.py --bio 案.txt    # bio（上限160）
```

全角は1文字＝2、URLは長さに関わらず一律23で数えられるため、**体感よりずっと早く上限に達する**。
日本語のみなら実質130字程度が上限。

**270を超えたら短くする。** 上限ぎりぎりだと、ユーザーが一言直しただけで超過する。

## 文体のルール

| 項目 | 設定 |
|------|------|
| 一人称 | わたし |
| 語尾 | です・ます。「〜と思います」「〜かもしれません」で断定を避ける |
| テンション | 中。落ち着いているが冷たくない |
| 絵文字 | 0〜2個。使うなら文末に1つ程度 |
| 感嘆符 | 1投稿につき1つまで |
| 書き出し | 挨拶は書かない。具体的な話からいきなり始める |

### 使わない

- 煽り、危機感の押し売り（「知らないと損」「9割の親が間違えている」）
- 強い断定（「絶対に」「必ず」）
- 他者・他教材への批判
- 子どもや保護者を下に見る表現、誤答をからかう表現
- 「バズ」狙いの過度な一般化
- テンションだけ高くて中身のない文（「今日も頑張ります！」など）

### リンク

**原則としてURLを入れない。** Xは外部リンクを含む投稿の表示を抑える傾向があり、
導線はプロフィール欄に集約する方針。

URLを入れるのは、**新単元の公開など告知の場面のみ**。入れる場合は
`https://wakaru-dekita-site.com/` を末尾に置く。

## 守るべき制約

- **エピソードを創作しない。** 現場の具体的な出来事は最も強い素材だが、
  Claudeが作り話を書いてはいけない。エピソードを使う型を提案する場合は、
  **枠だけ示して「ここはご自身の実体験に差し替えてください」と明示する**
- **児童・保護者・同僚が特定されうる内容を書かない。** 具体例は一般化する
- **勤務校が特定される情報を書かない**（校名、地域、行事の詳細）
- **算数の内容は必ず検算する。** 問題を出す場合、答えと解説が正しいことを確認する。
  教員のアカウントが計算を間違えると信頼への打撃が大きい

## 出力の形式

案ごとに次を示す。

```
### 案1: （切り口の説明）

（本文）

→ 248/280
```

最後に、どれを推すかと理由を1〜2文添える。迷わせないこと。
