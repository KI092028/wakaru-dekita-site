# ゲーム性の要素（ota tools の分析と、ここへの取り込み方）

作成日: 2026年8月
状態: **#1（分度器に目分量）・#4（都道府県）・#3（対戦）をすべて実装済み（2026-08）**

---

## 0. なぜこの文書があるか

[concept-review.md](./concept-review.md) で、**マップ・コンボ・テンポ改善は手応えを生まなかった**
と結論している。理由は「いずれも中核の体験の外側に置いた層であり、
中核（選択肢から選ぶだけ・意思決定なし・リスクなし）を変えていなかった」こと。

そのあと、同じく小学校教員が1人で作っている
[ota tools](https://otatools.github.io/toolbox/)（30アプリ・うち18がゲーム）を読んだ。
**あちらのゲームは中核そのものがゲームで、点数はその結果でしかない。**
ペンギンカーリングから「勝敗」を抜いたら何も残らないし、
目測角度から「予想する」を抜いても何も残らない。

つまり**既存のドリルに点数・ランク・コレクションを被せるのは、失敗した道の再走**になる。
効くのは、中核に**意思決定と、外れ方の幅**を入れるほう。この文書はその区別のために置く。

> ソースは `git clone https://github.com/otatools/toolbox` で読める。
> このサイトの外向き通信は制限されており、URLを貼っても取得できない。
> GitHub にソースがあるサイトは、リポジトリ名が分かれば読める。

## 1. 抜き出した要素

| # | 要素 | ota tools での例 |
|---|------|-----------------|
| 1 | **勝敗がある**（正誤ではなく） | ペンギンカーリング、3つだけ○×、推理ゲーム |
| 2 | **段階評価**（二値でない） | 目測角度：誤差0=ピッタリ／≤10=クリア成功／それ以上=ズレが大きい |
| 3 | **操作そのものが気持ちいい** | サイコロ「何のために使うかではなく、気持ちよく転がしたくて作った」 |
| 4 | **積み上がって見た目が変わる** | しりとり：語彙100個ごとにシカの絵が変化／星のすな→ランクアップ |
| 5 | **アンロック** | 魔方陣：全クリアで4×4の裏モードが開放 |
| 6 | **難易度を自分で選び、それぞれに記録** | 目測角度：3段階×2モード、難易度ごとにベストと連続記録 |
| 7 | **間違いを裏で数えて出題に効かせる** | 都道府県マスター「間違えた都道府県を裏でカウント」 |
| 8 | **教室で複数人** | 親機/子機、1台を回す |
| 9 | **音** | success/fail、「終了の音に異様なこだわり」 |
| 10 | **題材が教科の中にある** | 環状線タイピング=社会、回路パズル=理科、魔方陣=算数の発展 |

**10 が土台。** 勉強にゲームを被せているのではなく、**勉強をゲームに翻訳している。**

## 2. このサイトに取り込んだもの

### 2.1 段階評価（要素2）— 実装済み

このサイトはこれまで全単元が「正解／ざんねん」の二値だった。
**近さに意味がある場面では、二値は情報を捨てている。**

| 単元 | 段階 |
|------|------|
| 都道府県（→ requirements 5.13） | 正解／同じ地方（おしい）／別の地方（方角を返す） |
| 分度器の目分量（→ requirements 5.11） | ピッタリ／いい線いってる／まあまあ／だいぶちがった |

### 2.2 分度器に「目分量で予想」の手を足した（要素2・10）— 実装済み

ota tools の目測角度の説明が、こちらの分度器単元とまったく同じ問題を指していた。

> 分度器の数字をきちんと読んでいるのに、**50°を130°と答えてしまう子**に
> 「ぱっと見で90°より大きくないって分かるやん！」とツッコミを入れたくなります。

こちらが `requirements.md` 5.11 に書いた「内側と外側の読み違いがこの単元で最も多いつまずき」と同じ。
ただし**解き方が違う**。

- こちらの分度器：**道具の当て方**を直す（0をどちらのはしに合わせたか）
- 目測角度：**そもそも見当がついていない**ことを直す

この2つは対立せず、組み合わさる。測る前に「だいたい何度？」を1手置いた。

**この手に正解・不正解はない。** 予想なので外れて当たり前。
値打ちは、測ったあとに自分の見当と見くらべられること。
さらに、**予想のほうが正しかったときにそれを指摘できる**ようになった。

> 自分で 140度くらいと 予想したのに、40度 と 読んだね。
> 予想のほうが 合っているよ。0 を 合わせた 辺から 数えなおそう

「内側と外側を取りちがえた」の正体は、たいていこれ。

### 2.3 間違いを裏で数える（要素7）— もともとあった

九九マップ（`lib/quiz/progress.ts`）と手ごとのつまずき記録（`lib/practice/record.ts`）が
すでにこの形。都道府県も同じ仕組みに載せた（`lib/geo/progress.ts`）。

### 2.4 積み上がって見た目が変わる（要素4）— 都道府県で実装

**地図そのものが記録の表示**になっている。おぼえた県から色がつき、名前が出る。
白いところが残りの県。シカの絵が変わるのと同じ働きを、教材そのものにさせている。

### 2.5 難易度を自分で選ぶ（要素6）— 都道府県で実装

地方をえらぶと、その地方だけが大きく出る。地方ごとに「◯/◯県」を出す。
47県を1画面に入れると1マスが小さいので、**範囲をせまくしたぶんがマスの大きさに回る**。

## 4. 判断の基準（次に足すときはここを見る）

新しいゲーム性を思いついたとき、**その要素を抜いたら中核が残るかを先に見る。**

- 抜いても中核が残る（点数・ランク・見た目の変化だけ）→ **外側の層**。前に効かなかった道
- 抜くと何も残らない（勝敗・予想・選択・外れ方の幅）→ **中核**。ここを変えるなら意味がある

段階評価は例外的に安く効く。**近さに意味がある場面**なら、二値をやめるだけで
判定が情報を持ちはじめる（となりの県、目測のズレ、数直線の位置）。
逆に、近さに意味がない場面（九九の答え）で無理に段階にしても、何も増えない。

## 5. 対戦を入れてみて（2026-08）

`/learn/product-game`「かけ算じんとり」を作った。Product Game（1〜9のこま2つ、
積のマスを取り、たて・よこ・ななめに4つならべたら勝ち）を、1台を2人で回す形にしたもの。

**4の基準は満たしている。** 勝敗を抜くと何も残らない。
点数を被せただけの「外側の層」とは別のものになった。

作ってみて分かったこと。

- **盤の大きさが、ルールを決めていた。** 1〜9どうしをかけた答えは
  ちょうど36通りしかない（60や11のように九九では出ない数があるため）。
  6×6にぴったり収まるので、余りも足りないところも出ない。
  この一致がなければ、このゲームは成立していない
- **効くのは「どのマスを取るか」ではなく「相手に何を渡すか」。**
  こまは1つしか動かせないので、自分が取ったあとに相手が取れる範囲が決まる。
  九九を覚えているだけでは勝てず、逆から考えることになる。
  ここが、これまでのドリルには無かったところ
- **記録を取らないことにした。** 勝ち負けを端末に残しても、
  次にやることが分かるわけではない。このサイトではじめて
  localStorage を使わない単元になった
- **先手が2つ置くだけの手**は、本家のルールどおりにした。
  ここで取れると先手が有利になりすぎる

**検証のしかたが、1人用の単元とちがった。** 出題を500セット作って調べる形が
使えないので、**ランダムに500回対戦させて**、1手でマスが1つだけ増えるか、
こまが1つしか動かないか、終わったあとに手が通らないか、を見ている。
500回のうち449回が4つならびで決着した（残りはマスの数と引き分け）。
ここが0になるようだと、盤かルールがおかしいということになる。
