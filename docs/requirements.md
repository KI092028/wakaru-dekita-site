## 2. 目的とコンセプト

**「わかった」「できた」という達成感を、短いサイクルで積み重ねられる場をつくる。**

- 1問あたり10秒程度、1セット10問で完結する
- 説明を読ませるのではなく、すぐ問題に取り組める
- 正解・不正解をその場で返し、最後に点数で振り返る

### 想定する利用シーン

- おでかけ前、待ち時間などの**すきま時間**
- 宿題の前後、自主学習の時間などの**おうち学習**

## 4. スコープ

### 4.1 対象とするもの

- **教科は算数・社会・国語**（`QuizUnit.subject`）。単元マスタに教科を持たせ、画面はそこから組み立てる
- ブラウザで完結する練習。**4しゅるいある**
  - **ドリル**（3単元）：1セット10問。答えは打たせる
  - **1手ずつ**（5単元）：ひっ算を手順どおりに進め、どの手で止まったかを記録する
  - **図で考える**（2単元）：分度器・二重数直線。答えを打たせない単元もある
  - **ゲーム**（1単元）：都道府県。さがす・当てる
  - **道具**（1単元）：原稿用紙。練習ではなく、書くときに使うもの
- 教員向けの資料（すきま時間の学級レク、授業での利用について）
- 学年ごとに並べた単元一覧（`grade` と `kind` を単元マスタに持つ）
- サイトの紹介（トップページ）と、規約・ポリシーなどの静的ページ

### 4.2 対象としないもの（現時点で意図的に持たない機能）

- ユーザー登録・ログイン
- **サーバー側での**学習履歴の保存
  （ブラウザ内への記録は行う方針。→ 10.1）
- 保護者向けのレポート機能
- 有料プラン、課金要素（当面。→ 10.1）
- サーバーサイド処理（静的サイトとして運用する）

### 5.2 ドリルの共通仕様

**ここは「ドリル」3単元（たし算・ひき算／九九／分数）の話。**
ひっ算と図の単元は別の作りになっている（→ 5.7 以降）。

出題・判定・進行の挙動は**3単元で完全に共通**。実装も `components/quiz/quiz-game.tsx` 1つに集約している。
単元ごとに違うのは「問題の作り方」と「九九マップを出すかどうか」だけ。

- **1セット10問**。ページを開いた時点で10問を用意する
- **答えは選ばせず、画面内の数字キーパッドで打たせる**（選択肢は持たない）。
  端末のキーボードは出さない（低学年には操作が難しく、画面が覆われる）
- 整数は1枠、分数は**分子・分母の2枠**。分数の枠はタップで切り替えられるほか、
  右下の大きいボタンが分子入力中は「ぶんぼへ」に変わる
- 先頭の 0 は「0」単独のときだけ許す（ひき算の答えが 0 になりうるため。「05」は入力できない）
- **分数は約分し終えた形だけを正解とする。** `2/4` は誤答として扱い、約分をうながす
- 正解すると「せいかい！」を出し、**約0.55秒で自動的に次の問題へ進む**（「つぎへ」は押さない）
- 不正解のときは止まり、次の3つを出す
  1. 誤答の型が分かれば**何を間違えたか**を1行で言う（→ 5.3）
  2. 正答
  3. 「もういちど うってみる」ボタン
- 打ち直し（訂正的検索）で正しく入力すると次へ進む。**このときは得点も習得記録も動かさない**
- 画面上部に「n / 10 もん目」と「とくてん」を常時表示する
- 10問終えると結果画面に切り替わり、**n / 10 もん**の形式で得点を表示
- 「もういちど挑戦する」で**新しい10問**を用意して最初から再開する

### 5.3 誤答の型を返す

不正解のとき、打たれた答えの形から何を間違えたかを判定して1行で返す（`lib/quiz/diagnose.ts`）。
判定できないときは正答の提示だけにとどめる。

| 単元 | 拾っている誤答 | 返す言葉 |
|------|----------------|----------|
| 九九 | `a×(b±1)` / `(a±1)×b` | 「おしい！ ◯のだんの ひとつ となりの こたえだよ」 |
| 九九 | `a+b` | 「たし算に なっているよ。ここは かけ算だね」 |
| たし算・ひき算 | 逆の演算の答え | 「しるしを 見てみよう。ここは たし算だよ」 |
| たし算・ひき算 | 正答との差が 10 | 「くり上がり／くり下がりを わすれていないかな」 |
| たし算・ひき算 | 正答との差が 1 | 「あと 1 だけ ちがうよ。かぞえまちがいかも」 |
| 分数 | 値は合っているが約分前 | 「あと ひといき！ その分数は もっと かんたんに できるよ」 |
| 分数 | 分子どうし・分母どうしを計算 | 「ぶんしどうし・ぶんぼどうしを 計算していないかな。さきに つうぶんだよ」 |
| 分数 | 通分はしたが分子を直し忘れ | 「つうぶんは できているね。ぶんしにも 同じ数を かけよう」 |
| 分数 | 分母だけ合っている | 「ぶんぼは あっているよ。ぶんしを もういちど」 |

ここに並ぶ誤答は、4択時代に「誤選択肢」として持っていた知識をそのまま移したもの。
選択肢は廃止したが、**つまずきの型という資産は捨てていない。**

#### 分数の設計（実装済み）

子どもがつまずくのは計算そのものより、**通分と約分の作業**である。
そのため同分母の計算だけでは実際の弱点に効かない。1セット10問の中で、
レベル選択のUIを設けずに次の順で難しくしている。

1. 同分母のたし算・ひき算（導入・2問）
2. 片方の分母がもう片方の倍数（通分の入口・3問）
3. 最小公倍数で通分（つまずきの本丸・3問）
4. 答えの約分が必要（2問）

**答えは既約分数でのみ正解とする。** 2/4 のような約分前の形は誤答として扱い、
「もっとかんたんにできる」と返す。約分こそがこの単元の練習対象なので、
値が合っていれば通す作りにすると素通りできてしまう。

子どもが実際にやりがちな間違い（「分子どうし・分母どうしを足す」など）は、
かつて誤選択肢として持っていたが、いまは誤答の型として `diagnose.ts` に置いている（→ 5.3）。

問題として提示する分数は既約にそろえる。3/6 − 1/6 のように問題側が約分できると、
答えを約分する練習の前に問題を約分してしまい、何を問われているかがぼやけるため。

#### 単元構成の考え方

将来的には、**教科書における小学校6年間の単元構成の順番**に沿って問題を用意したい。
学年ごとに何を学ぶかの流れに沿って単元が並んでいれば、
「今習っているところ」を選びやすくなる。

現時点の単元一覧は少数の単元を並べているだけだが、
単元が増えてきた段階で、学年・履修順を持たせた構成へ整理する。

準備中の単元はカードを淡色表示し、リンクを持たせない。
`lib/quiz/units.ts` の `available: false` で制御している。

お問い合わせフォームも未実装（`/contact` は準備中の案内のみ）。

### 5.6 九九マップ（九九のみ）

81マスの習得状況を持つのは九九だけ。他の2単元は毎回ランダムに出題する。

> **注意: マップ・コンボ・テンポ改善は手応えを生まなかった。**
> 原因を理論と実証から調べた結果を [game-design-research.md](./game-design-research.md)、
> [cognitive-science-research.md](./cognitive-science-research.md)、
> [concept-review.md](./concept-review.md) にまとめてある。
> 要点は「マップ・コンボ・テンポ改善はいずれも中核の体験の外側に置いた層であり、
> 中核（選択肢から選ぶだけ・意思決定なし・リスクなし）を変えていなかった」こと。
> **本節を実装の指針として読む前に、必ず調査文書を参照すること。**

#### しくみ

- 九九ページの上部に **9×9＝81マスの表**を置き、各マスの習得状況を色で示す
- 状態は 未挑戦 / れんしゅう中 / マスター / にがて の4つ
- **連続2回正解でマスター。** かつては「4択では偶然当たるから2回」という理由だったが、
  入力式にしたいまは「1回の正解では定着とは言えず、別のセットでもう一度出会って
  正解する必要がある」という理由で2回にしている
- **一度マスターしたマスは、あとで間違えても取り消さない。** マスター数が減るのは罰になる
  （ただし出題では優先的に再登場させる）
- 結果画面に「あたらしく◯マス マスターしました」「のこり◯マス」を表示する
- **はじめての1セットではマスターが必ず0になる**（10問はすべて別のマスなので、
  同じマスに2回出会わない）。9問正解したのに「のこり81マス」とだけ出ると
  何も進まなかったように見えるため、新規マスターが0のときは
  **「あと1回 せいかいすると マスターに なる マスが ◯マス あるよ」**を先に出す

#### 出題の優先順位

にがて → **あと1回でマスター** → 未挑戦 → マスター済み（復習）

「あと1回でマスター」を未挑戦より先に出すのが要点。未挑戦から消化すると
81マスを一巡するまでマスターが1つも増えず、進んでいる実感が出ない。
さらに「あと1回」と「未挑戦」を交互に混ぜることで、
毎回およそ5マスずつ安定してマスターが増えるようにしている。

#### コンボ表示は撤去した

「◯れんぞく」の表示は、調査で**苦手な子ほど失敗の可視化装置として働く**と指摘されており、
3単元の操作感をそろえる際にあわせて撤去した。他単元へ広げる選択肢もあったが、
効果がないと分かっているものを広げる理由がない。

#### 採用しなかったゲーム性と、その理由

| 要素 | 見送った理由 |
|------|-------------|
| デイリーストリーク（連続日数） | 再訪動機としては強いが、**通知を送れない静的サイトでは機能しにくい**。途切れたときの罪悪感も低学年には重い |
| タイムアタック | 焦りでミスが増え、算数嫌いの原因になりうる |
| ランキング・他者比較 | 低学年では劣等感につながり学習を阻害する。そもそもサーバーがないため実現もできない |
| ガチャ・コレクション報酬 | 射幸性が高く、保護者の信頼を損なう |

#### 保存について

習得状況は **端末のlocalStorageにのみ**保存する（キー: `wakaru-dekita:times-table:v1`）。
サーバーには送らない。端末やブラウザを変えると引き継がれず、
ブラウザのデータ削除で消える。この点は**画面上とプライバシーポリシーの両方に明記**している。

localStorageが使えない環境や保存内容が壊れている場合は、
記録なしとして扱い、学習そのものは続けられるようにしている。

### 5.7 わり算のひっ算

3単元のドリルとは性質が違う。**1問1答ではなく手続きの練習**なので、
答えだけを合わせても意味がない。UIも別に用意している（`components/division/`）。

#### つまずきを4つに分けて扱う

わり算のひっ算でつまずく子は、「わり算ができない」のではなく、
次のどれかで止まっていることが多い（現場での見立て）。

1. **九九がパッと出ない** — 手順を追う余力が九九の思い出しに取られる
2. **手順そのものを覚えていない** — たてる・かける・ひく・おろす の順が定まらない
3. **どこに商を立てるか分からない** — 位取りの理解
4. **ひき算（くり下がり）で崩れる**

これらは別々の力なので、まとめて「不正解」にすると本人にも何ができていないか分からない。
そこで1手ごとに区切り、**どの手で止まったかを別々に数える**。

| つまずき | 手当て |
|----------|--------|
| 九九が出ない | 除数の段の九九を、開けば見られるようにする（既定は閉じる）。ここでの目的は手順の習得なので、九九は見てよいことにした |
| 手順を覚えていない | **たてる→かける→ひく→おろす を常に画面に表示**し、いまどれかを示す。手順を思い出すことに気を取られて計算が崩れるのを防ぐ |
| 商を立てる位置 | 最初に「商はどこに立つか」を、ひっ算の上のわくをタップして答えさせる。ずれたら「ひとつ右だね」と方向を返す |
| くり下がり | ひくの手で、たし算・ひき算の誤答診断をそのまま使う |

#### 出題

1セット**4問**。ひっ算は1問に何手もかかるため、10問だと最後まで持たない。
段階は固定で、つまずきの種類ごとに1問ずつ当たるようにしてある。

問題は、条件に合うものが出るまでランダムに引いては手順を組んで確かめる方式で作る。
段階の判定にひっ算の手順そのものを使うほうが、条件を数式で書き下すより間違いが少ない。
いちばん当たりにくい段階でも20回に1回は当たるので、数十回引けば足りる
（全組み合わせを先に並べる作りにすると、端末で7万通り分の計算が走るためやめた）。

| 順 | 内容 | ねらい |
|----|------|--------|
| 1 | わりきれる2けた÷1けた | 手順そのものに集中させる。商に0が立つ形は避ける |
| 2 | あまりのある2けた÷1けた | ひく の意味 |
| 3 | 3けた÷1けた・はじめのけたで割れない | どこに商を立てるか |
| 4 | 3けた÷1けた・商に0が立つ | いちばんの難所 |

#### 2けたでわる（別単元）

**1けたでわる／2けたでわるは別のページに分ける**（教科書でも3年と4年で分かれている）。
2けたでわるほうは「仮の商の見当をつけて、合わなければ1つ増減する」という
別の技能が中心なので、同じセットに混ぜると何を練習しているのかがぼやける。

出題の段階：

| 順 | 内容 | ねらい |
|----|------|--------|
| 1 | 仮の商がそのまま合う | がい数で見当をつけるやり方に慣れる |
| 2 | 仮の商を1つ減らす | 23 を 20 と見たぶん、仮の商が大きく出る |
| 3 | 仮の商を1つふやす | 19 を 20 と見たぶん、仮の商が小さく出る |
| 4 | 商が2けた | 段を2回まわす |

2けたでわるときだけ足しているもの：

- **たてる の手で、がい数のつけ方を毎回画面に出す**
  （「24 は だいたい 20。336 ÷ 20 で 見当を つけよう」）。
  覚えているかを試す場面ではないので、手順は見せてしまう
- 商がずれたときは「大きすぎる／小さすぎる」で終わらせず、
  **「ひとつ 減らしてみよう」「ひとつ ふやしてみよう」**と次の動作まで言う。
  仮商の修正こそがこの単元の中心なので
- かける の誤りは九九ではなく**2けた×1けた**の誤りとして見る。
  となりの積・くり上がりのたしわすれ・一の位だけ／十の位だけ を拾う
- ひく の誤りは、くり下がりの取りこぼしが 10・100 のずれとして出るのを拾う
- 打てる桁数を手ごとに変える（商は1けた、かけた数は3けたまで）
- 補助の表の見出しは「52 のだん」ではなく「52 × 1〜9 を 見る」にする

#### ドリルとそろえたところ／変えたところ

**そろえた**: 画面内の数字キーパッド、間違えたら止まって指摘＋正答、
「もういちど やってみる」で自分で打ち直す流れ、言い回し。

**変えた**: 正解しても間を置かず、すぐ次の手へ進む。
ひっ算は1問が長いので1手ごとに演出を挟むとテンポが死ぬ。
**書き足された数字が盤面に現れること自体が手ごたえになる**ため、演出は問題の完成時にまとめる。

#### 結果の見せ方

ひっ算は途中で投げ出さないかぎり必ず完成するので、「n問正解」は意味を持たない。
かわりに次の2つを出す。

- **1回で最後までできた問題数**（間違えずに通せたか）
- **まよったところの内訳**（たてる◯回／かける◯回…）

そのうえで、いちばん多かったつまずきに応じて戻る先を名指しする。
かける でつまずいていれば九九へ、ひく でつまずいていればたし算・ひき算へリンクする。
回数が同じときは**九九・ひき算を先に見る**。この2つだけが別の単元で直接練習できる＝
打ち手のあるつまずきだから。

#### 記録

**手ごとに「通った回数」と「止まった回数」を端末に保存する**。1セット通し終えた時点で書き足す。
1けたでわる／2けたでわるは別単元なので、記録も別のキーに分ける
（`wakaru-dekita:long-division:v1` / `wakaru-dekita:long-division-2:v1`）。

1回分の結果だけでは「たまたま間違えた」と区別がつかない。
何回やっても同じ手で止まっているのかが分かって、はじめて見立てになる。

- 見るのは回数ではなく**割合**。「かける 3回」は、かけるを何回通ったかが分からないと
  多いのか少ないのか判断できない
- 通った回数が **6回に満たない手は対象から外す**。1〜2回のつまずきで
  「ここが苦手」と決めつけないため
- 直近5セットぶんだけ「どの手で止まったか」を覚えておき、
  「さいきんの3回のうち3回」という形で出せるようにしている

**表示は結果画面だけにとどめる。** 常に見える場所に「苦手: かける」と出すのは、
コンボ表示と同じく失敗の可視化装置として働きうる。
言い方も不足ではなく方向として書く（「九九を すこし れんしゅうすると 楽になる」）。

保存は九九と同じ扱い。localStorage が使えない環境や内容が壊れている場合は
記録なしとして扱い、練習そのものは続けられるようにしている。
端末内にのみ保存する旨は**結果画面とプライバシーポリシーの両方に明記**している。

### 5.8 教員向けエリア（`/teachers/`）

児童向けドリルとは**読者が違う**ため、URLとナビゲーションで分離している。
設計の経緯と掲載内容は [class-rec-spec.md](./class-rec-spec.md) を参照。

#### 分離の仕方

- **ヘッダーには出さない。** 児童が見るナビゲーションは変えない
- 導線は**フッターの「先生の方へ」1リンク**のみ。教員は検索から
  `/teachers/rec/` に直接着地する想定なので、トップからの導線に依存しない
- 文体を切り替える。ドリルはひらがな主体だが、ここは通常の漢字表記

#### 学級レクの掲載条件

数を並べることを目的にしない。次を**すべて**満たすものだけ載せる。

1. 5分以内に終わる（説明込み）
2. 準備物が「なし」または「黒板とチョーク」まで
3. 教室で成立する（体育館・校庭を必要としない）
4. ルール説明が30秒で済む
5. 人数が多少ぶれても成立する

**条件を満たさないものは、良いレクでも載せない。** 網羅型の記事は準備物ありや
体育館ありが混ざっていて、隙間時間に開いた教員には大半が使えないため。

#### 絞り込み

時間（2/3/5分以内、累積）・声の大きさ・隊形・準備物なし の4軸。
**「声の大きさ」が要点。** 隣のクラスが授業中だと、盛り上がるレクは候補から外れる。

#### 算数との接続

10件のうち3件（3の倍数で手をたたく／数当て／31ゲーム）は算数と地続きにしてある。
`relatedUnit` を持つものは詳細ページから該当ドリルへリンクする。

### 5.9 たし算・ひき算のひっ算／小数のたし算・ひき算

わり算のひっ算と同じ「1手ずつ進める手続きの練習」。実装は `lib/column/` と
`components/column/` にまとめ、**整数と小数を同じ部品で扱う**（`ColumnGame mode="integer" | "decimal"`）。

わり算は「段」で進むが、こちらは**位ごとに右から左へ**進む。構造が違うので
`lib/division/` とは型を共有していない。共有しているのはキーパッド・誤答時の流れ・記録の仕組み。

#### 手を3〜5種類に分ける

| 手 | 内容 | 入力 |
|----|------|------|
| `write` | その位の答えを書く | 数字 |
| `carry` | くり上がりの1を**ひとつ左の位の上に置く** | 位のタップ |
| `borrow` | 借りたあと、左どなりがいくつになるかを書く | 数字 |
| `pad` | けたをそろえる 0 を書く（小数のみ） | 数字 |
| `point` | 答えの小数点を打つ（小数のみ） | すきまのタップ |

**くり上がりを数字入力ではなく位のタップにしてある。** 書く数（1）は決まっていて、
つまずくのは「どこに書くか」のほうだから。小数点も同じ理由ですきまを選ばせる。

#### その位の計算をまとめて打っても正解にする

1 + 7 + 8 の位で **16 と打つのを正解として受け取る**（書かれるのは一の位の 6）。

頭の中では 16 まで出してから 6 を書き 1 をくり上げるので、16 と打つのは
手順が分かっていない証拠ではなく、むしろ自然な打ち方。
かつてはこれを誤答として「16 のうち この位に 書くのは 6 だけ」と返していたが、
**正しく計算できた子に「ざんねん」を返していた**ことになる。

くり上がりの手の問いは「16 の くり上がりの 1 は どこに 書く？」とし、
まとめて打った子にも、6 だけ打った子にも同じようにつながるようにしてある。
かけ算のひっ算の九九の手（42 と打つ）も同じ扱い（→ 5.10）。

ひき算の誤答診断には Brown & Burton (1978) が挙げた代表的な手続きのバグを入れている。
中でも**上下をひっくり返して引く**（ひけないので大きいほうから小さいほうを引く）は
最も多いので、専用の言葉を返す。

#### 小数で足していること

つまずきは計算ではなく**そろえる作業そのもの**にあるので、計算より先にそろえさせる。

- けたが足りない側に 0 を書き足す手（`pad`）を先頭に置く
- 続いて**答えの小数点を打つ位置**を決めさせる。上下の小数点とたてにそろう位置を選ばせる
- ただし盤が2けたしかない（すきまが1つしかない）ときは選ぶ余地がないので、
  手として問わず最初から打っておく
- 内部では 10ⁿ 倍した整数として扱い、整数のひっ算の手順をそのまま使う

#### 出題

1セット**6問**（わり算より1手あたりが軽いので4問ではなく6問）。段階は固定。

整数：くり上がりなし → くり上がり1回 → くり上がり2回（3けた）→
くり下がりなし → くり下がり1回 → くり下がり2回（3けた）。

**くり上がり／くり下がりは一の位から起きる形に限る。** 十の位だけでくり上がる問題
（54+83）は指導の順序が違うため、この段階では出さない。
0のとなりから借りる形（302−158）は借りが2つ左まで連鎖する別の難所なので出さない。

小数：小数第1位どうし（くり上がりなし／あり）→ けた数がちがうたし算 →
同じ3段階のひき算。**けた数がちがう形**を必ず1問ずつ入れて、そろえる練習にする。

記録は単元ごとに別キー
（`wakaru-dekita:column-add-sub:v1` / `wakaru-dekita:column-decimal:v1`）。
仕組みは 5.7 と同じで、`lib/practice/record.ts` を共通で使う。

### 5.10 かけ算のひっ算

盤の作りが他と違う。たし算・ひき算は1行で答えが出るが、かけ算は
**かける数のけたごとに1行（部分積）**ができ、最後にそれを足す。
そのため盤だけは別に用意している（`components/multiply/multiply-board.tsx`）。
最後のたし算は、たし算のひっ算の手順（`buildColumnPlan`）をそのまま使う。

#### 手を4つに分ける

| 手 | 内容 | 入力 |
|----|------|------|
| `product` | その位の九九の答えを書く（10以上なら一の位だけ） | 数字 |
| `carry` | くり上がりを**ひとつ左の上に書きとめる** | 数字 |
| `shift` | 2だんめを**どこから書きはじめるか** | ますのタップ |
| `add` | 部分積どうしを足す | 数字 |

**`shift` を独立した手にしてあるのが、この単元の中心。**
「なぜ1つずらすのか」が分からないまま形だけ覚えている子はここで必ず止まるので、
それが記録に残る。誤答には方向を返す
（「2だんめは かける数の 十の位を かけているね。だから ひとつ 左から 書きはじめるよ」）。

たし算のくり上がりが**位のタップ**なのに対し、かけ算のくり上がりは**数字入力**。
書く数が 1 で固定ではなく 0〜8 になるうえ、その値を出すこと自体が練習だから。

いちばん左からあふれるけたは、上に書かずそのまま答えの位に書く（紙のひっ算と同じ）。
書きとめる場所がないので、**直前の計算を問いの中で示す**
（「2 × 8 + 5 = 21。くり上げる 数を、いちばん 左に 書こう」）。

#### 出題

1セット**4問**。2けた×2けたは1問13手あるため、6問だと最後まで持たない。

| 順 | 内容 | ねらい |
|----|------|--------|
| 1 | 2けた×1けた・くり上がりなし | 手順そのものに集中させる |
| 2 | 2けた×1けた・くり上がりあり | くり上がりを書きとめる |
| 3 | 2けた×2けた・くり上がりなし | **ずらすことだけに集中させる** |
| 4 | 2けた×2けた・くり上がり2回以上 | 通しでできるか |

一の位が 0 の数は九九の手がひとつ消えるので使わない。
3問目は、かけられる数の十の位と一の位が同じ数（22×31）も避ける
——全部同じ九九になり、考えずに同じ数を書けてしまうため。

九九の手では、**まとめて打った値（7×6 を 42）も正解にする。**
理由は列のひっ算と同じ（→ 5.9）。単元ごとに扱いを変えない。

記録は `wakaru-dekita:column-multiply:v1`。戻る先は
`product` なら九九、`add` ならたし算のひっ算へリンクする。

### 5.11 角の大きさ（分度器）

ここまでの単元と種類が違う。**答えを出す手続きではなく、道具の当て方**を練習する。
分度器の使い方は説明を読んで分かるものではなく、ずれた状態から自分で合わせてみないと
身につかない。紙の上では教師が横について直すしかない場面で、
画面ならその役をある程度まかなえる、というのがこの単元を作った理由。

#### 手を4つに分ける

| 手 | 内容 | 操作 |
|----|------|------|
| `guess` | はかる前に、目分量で何度かを予想する | 数字キーパッド |
| `place` | 分度器の中心を、角のいただきに合わせる | 分度器をドラッグ（平行移動） |
| `align` | まっすぐなへり（0の線）を辺にかさねる | 分度器をドラッグ（中心まわりの回転） |
| `read` | 目もりを読む | 数字キーパッド |

**同じドラッグに、手ごとに違う意味を持たせている。** 移動と回転を同時に扱わせると
指が3方向に取られて、何をしているのか分からなくなるため。
`read` の手では分度器は動かせない。**自分が置いた分度器のまま読ませる**ことが要点で、
きれいに当たった状態を用意して読ませるのでは、当て方の練習にならない。

手が終わるたびに、ぴったりの位置・向きに寄せる（スナップする）。
わずかなずれを残したまま目もりを読ませても読み方の練習にならないため。

#### 合わせ方は2通りとも正解にする

まっすぐなへりの**右はしを辺に合わせても、左はしを合わせてもよい**。
そのとき 0 から数える目もりが入れかわるだけで、読み取れる角の大きさは同じ。
**これが目もりが2しゅるいある理由そのもの**なので、両方を通す。

内側と外側の読み違い（60度を120度と読む）は、この単元で最も多いつまずき。
「内側を見なさい」ではなく、**自分が 0 を合わせたのはどちらのはしか**に立ち返らせる。

そのうえで、**左の 0 を使わないと自然に解けない問題を半分入れている。**
水平な辺が右向きの図ばかりだと、右の 0 だけで最後まで通せてしまい、
目もりが2しゅるいある理由に一度も出会わずに終わる。
水平な辺を左向きにすると、右の 0 では角が半円に入らないので、
**左の 0 を使うか、分度器をひっくり返すか**を自分で決めることになる。

このとき「へりは辺に重なっているが、角が分度器の外に出ている」置き方を必ず通る。
ここは「へりがずれている」ではなく **「ひっくり返そう」** と言わないと、
何を直せばよいのか分からない。専用の言葉を返している。

> 0 を 合わせた 辺から 数えよう。いま 0 は 右はし に あるから、
> 右はしの 0 から 進む ほうの 目もりだよ

この言い方なら、左はしに合わせた子には「左はし」と返る。
分度器の作り（どちらの環が内側か）にも依存しない。

#### 出題

1セット**6問**。1問3手と短いので、ひっ算より多くとれる。
**右の 0 を使う形と、左の 0 を使う形を3問ずつ**にしてある。

| 順 | 内容 | ねらい |
|----|------|--------|
| 1 | 鋭角・右に0・水平 | 当て方そのものに集中させる |
| 2 | 鈍角・右に0・水平 | 内側・外側の読み違いが出る |
| 3 | 鋭角・左に0・水平 | ひっくり返す必要に出会う |
| 4 | 鈍角・左に0・水平 | 左の 0 から数える |
| 5 | 直角に近い角・かたむき（右に0） | 90度ちょうどは避ける（分度器を使わずに分かるため） |
| 6 | 鈍角・かたむき（左に0） | 通しでできるか |

はじめの分度器の向きは、**2つある正しい向きのどちらからも25度以上離す。**
片方しか見ていないと、たまたま最初から合っている問題が出る。

図の外わくは、**分度器がどちらを向いても収まる大きさ**にとってある
（いただきを中心に半径130の円が入る 400×380）。
上向きだけを想定した大きさだと、左の 0 の問題で半円が下を向いたときに
分度器が画面の外に出てつかめなくなる。

**角の大きさは5の倍数に限る。** 4年では1度きざみまで読むが、
画面では半径130pxに180本の目もりが並び、1度の差は指では読み分けられない。
ここで測るのは当て方と「どちらの目もりを見るか」なので、
読みの細かさを問うのは紙にゆずる。

#### 目分量の予想（`guess`）

**この手に正解・不正解はない。** 予想なので外れて当たり前。
値打ちは、測ったあとに自分の見当と見くらべられること。
予想の手のあいだは分度器を出さない（目分量なので）。

当たり具合は、測り終えてから見せる。先に出すと答えが分かってしまう。

> だいぶ ちがったね
> 予想 170° → じっさい 45°
> ズレは 125度。この角は 直角（90度）より 小さいよ。よく見てみよう

外れ幅で4段階（ピッタリ／いい線いってる／まあまあ／だいぶちがった）。
直角より上か下かだけでも当たっていれば、そこは認める。

**いちばんの値打ちは、予想のほうが正しかったときに、それを指摘できること。**

> 自分で 140度くらいと 予想したのに、40度 と 読んだね。
> 予想のほうが 合っているよ。0 を 合わせた 辺から 数えなおそう

内側と外側の読み違いの正体は、たいていこれ。

### 5.13 都道府県（社会）

**社会科の1単元目。** 教科の軸を入れて最初に置いたもの。

名前が出るので、地図の上でその県を押す。

#### 正解・不正解の2つで終わらせない

地図では「近い」に意味がある。となりの県を押したのと、まったく違う地方を押したのは
同じ「不正解」ではない。

| 押した先 | 返す言葉 |
|----------|----------|
| 正解 | せいかい！ |
| 同じ地方 | おしい！ 同じ 四国地方だよ。徳島県から見て 西 のほう |
| 別の地方 | そこは 九州・沖縄地方。もっと 北東 のほうだよ |

**模式図のマスの差から出している。**

#### 地図は実際の白地図

県境は `@svg-maps/japan`（Victor Cazanave, **CC BY 4.0**）のパスをそのまま描く。
CC BY は出典の表示が条件なので、ページ下に明記している。

`cx` `cy`（名前を置く場所）と `box`（外わく）は、実際のパスから測って書き出した値。
**離島があると外わくの中心が海の上に来る**ので、中心が本体の中に入るかを
`isPointInFill` で判定し、入らない9県（東京・長崎・沖縄など）は
輪郭をたどって点が集まるところを使っている。

- **正解した県には、名前が地図の上に出る。** 一度でも正解すれば出るので、
  進むほど地図に名前が増えていく
- **地方ごとに枠を引く。** 同じ地方の県を、その地方の色で太く縁どる。

  位置を覚えるための地図で別わくに入れると「沖縄はわくの中」と覚えてしまう

**小さい県のために、当たり判定を広げている。** 実際の形だと香川県・大阪府・東京都は
全国表示では指で押せない。県の中心に見えない丸を置き、パスの下に敷いてある。
県の中を押せばその県が取れ、すこし外れたときだけ近くの丸が拾う。

#### 記録

九九マップと同じ。連続2回せいかいで「おぼえた」、一度ついたら取り消さない。
出題は にがて → あと1回 → まだ → おぼえた の順。
キーは `wakaru-dekita:prefectures:v1`。

範囲えらびの画面に置いた。消えると困る記録なので、1回たしかめてから消す。

### 5.14 原稿用紙（国語）

**この単元だけ、練習ではなく道具。** 出題も判定も記録もない。
打った文章が、そのまま原稿用紙のマスに入る。

1枚は **縦15マス × 横20マス = 300字**。

#### マスの中に直接書かせない

入力欄とマス目を分けている。日本語は変換しながら打つので、
**変換中の字が1マスずつに散らばると打てなくなる。**
ふつうの入力欄に打ってもらい、確定した文をマスへ流し込む。

#### 縦書きと横書き

同じ 15×20 のマス目で、**流し込む向きだけが変わる。**

- 横書き：1行20マスが15行。左から右へ、上から下へ
- 縦書き：1行15マスが20行。上から下へ、**右から左へ**

縦書きでは、長音符（ー）など7字を90度まわして書く。
立てたままだと縦書きでは読めないため。

#### 禁則処理

「、」「。」「）」「っ」などが行のいちばん上に来ないよう、
**前の行の最後のマスに一緒に入れる（ぶら下げ）。**
開きカッコ（「（）が行の最後に来るときは、次の行へ送る。
原稿用紙を手で書くときと同じで、これをやらないと縦書きで句読点が行頭に落ちる。

#### 数えるもの

文字数（改行をのぞく）／空白もぬいた文字数／段落／用紙の枚数と、
最後の1枚で何マス目まで進んだか。

#### 印刷

**A4たて1枚に、原稿用紙1まい。** 入力欄・見出し・ヘッダー・フッターは印刷しない。
`break-after: page` で1まいずつページを分けている。

書きかけは端末の中だけに残す（`wakaru-dekita:manuscript:v1`）。
うっかり閉じても消えないようにするためで、サーバーには送らない。

### 5.12 単位量あたりの大きさ

**この単元だけ、数を打たせる場面がない。**
ここで練習するのは計算ではなく「どちらの量を 1 にそろえるか」と
「そろえた数が何を表すか」だから、答えを当てさせる形にすると壊れる。

#### なぜ計算をさせないのか

つまずきの本体は割り算ではない。**どちらの量で割るかを決められない**ことと、
出てきた商が何を表すか分からないことにある。
令和6年度の全国学力・学習状況調査でも「単位量当たりの大きさ（速さなど）について、
深い理解を伴う知識の習得やその活用に課題」と名指しされている。

公式を覚えて計算させるドリルにすると、意味が分からないまま答えが出せてしまい、
**むしろ有害**になる。だから A型（ドリル）にしていない。

#### 手を3つに分ける

| 手 | 内容 | 操作 |
|----|------|------|
| `base` | どちらの量を 1 にそろえるか | 2つから選ぶ |
| `align` | 二重数直線のしるしを 1 まで動かす（左右で1回ずつ） | ドラッグ |
| `compare` | どちらが こんでいる／うすい／速い か | 2つから選ぶ |

**`base` には誤りがない。** どちらの量を 1 にそろえても正しく比べられる。
手として置いてあるのは、選んだことを本人に意識させるため。

#### 「多いほうが答え」が反転する

たたみ 1まいあたりの人数なら**多い**ほうがこんでいるが、
子ども 1人あたりのたたみ枚数なら**少ない**ほうがこんでいる。
**この反転こそが「商が何を表すか」**であり、分度器の
「右の0か左の0か」（→ 5.11）とまったく同じ形をしている。

反転する側を選んで間違えたときは、値を並べたうえで
「この くらべ方では『少ない』ほうが こんでいるね」と返す。

#### 差でくらべる考え方を、正面から崩す

子どもは既定で**差でくらべる**（加法的方略）。国際的にも繰り返し報告されている。
「9人2まい」と「11人4まい」はどちらも差が7なので、差で比べる子はここで「同じ」と答える。

そこで **1問目は差が同じになる形、2問目は差では逆になる形**に固定してある。
この食い違いがないと、加法的な考え方のまま最後まで通せてしまう。
差で選んだと判定できたときは、それと名指しして返す。

#### 図

二重数直線。しるしを動かすと**上下の数がいっしょに動く**。
これが「そろえる」という操作の中身そのもので、割り算の式を先に見せると、この動きが見えなくなる。

- **左右2つの数直線で、同じ長さが同じ量を表す。**
  そうすると「1 のところ」が左右で同じ位置に来るので、そろえたあとの数を目で見比べられる
- しるしは目もりに吸いつく。ここで問うているのは位置の細かさではなく「1 にそろえる」という判断
- しるしは**まるごとの量のところ**から始まる（「たたみ 6まいに 子ども 8人」）。
  そこから 1 まで動かす操作が、そのまま「そろえる」になる
- 最後に、そろえた2つを**長さの帯**で見くらべる。数字だけだと差でくらべる考えに戻りやすい

#### 出題

1セット**4問**。1問4手だが、考えるところが重いので数は少なくする。

| 順 | 場面 | ねらい |
|----|------|--------|
| 1 | 混み具合（へや）・差で比べると同じになる | 差ではくらべられないことに出会う |
| 2 | 混み具合（シート）・差で比べると逆になる | 同上。逆になる形 |
| 3 | ジュースのこさ・「どちらが うすい？」 | 小さいほうが答えになる問い |
| 4 | 速さ（ミニカー） | 同じ考え方が別の場面にも使えること |

**どちらの量も 12 以下**にそろえてある。
1 にそろえる量は2通りとも選べる必要があり、ということは
どちらの量も数直線に目もりを引ける大きさでなければならない。
単価（4本で320円）のような組は、円のほうを 1 にそろえる操作が図にできないので使っていない。

記録は `wakaru-dekita:per-unit:v1`。

### 5.15 割合・百分率

**要件。** 5年の割合を、式ではなく数直線で扱う。1セット4問。

| # | 手 | 何をするか | 誤りがあるか |
|---|----|-----------|-------------|
| 1 | もとをさがす | 文に出てくる2つの量から、もとにする量をえらぶ | **ある** |
| 2 | 100%を置く | 数直線の、もとにする量のところへ 100% を動かす | ある |
| 3 | しるしを動かす | 求める場所（割合／量）へしるしを動かす | ある |
| 4 | 読む | しるしの反対がわの数を打つ | ある |

**式を書かせない。** つまずきの本体は計算ではなく、どれが「もとにする量」なのかを
文から決められないこと。公式（くらべる量 ÷ もとにする量）を覚えても解けないことが
この単元の問題そのものなので、式を立てさせる形にすると練習にならない。

**割合の目もりは、100% を置くまで出さない。** 下の線は最初は点線で目もりが無く、
もとにする量の上に 100% を置いた瞬間に 10% きざみの目もりが現れる。
割合は紙にもとから書いてある目もりではなく、**もとにする量を決めたことで
はじめて生まれる目もり**だから。

**線はもとにする量より長くとる。**「10%増量」が 100% の右に来ることを目で確かめられるように。
令和7年度の全国学力・学習状況調査では、この設問の正答率が 41.3% で、
誤答に「0.1倍」「10倍」が並んでいた。増量なのに元より小さい数を答えているので、
100% より左に置いたらその場で名指しする。

**単位量あたり（5.12）との違い。** あちらは「どちらの量を1にそろえるか」が
2通りとも正しかったが、割合ではもとは1つに決まる。**もとをえらぶ手に誤答がある。**

**出題の制約。**

- もとにする量は 10 の倍数。量の目もりはその10等分にする。
  こうすると目もり1つがちょうど 10% になり、量の目もりと割合の目もりが同じ場所で重なる
- **もとにする量が線の右はしに来ないようにする。** 右はしに固定されると
  「いちばん右」で当たってしまい、もとを読み取る練習にならない
- 4問の並びは固定：割合を求める → 量を求める → ふえる → へる。
  ふえるだけを出すと「いつも100%より右」で当てられる

### 5.16 時こく・時間

**要件。** 時計の針を自分で回す。1セット4問。

| # | 手 | 何をするか |
|---|----|-----------|
| 1 | 合わせる | 出発の時こくに長い針を合わせる（読むことの裏返し） |
| 2 | うごかす | ◯分すすめる／もどす |
| 3 | 読む | いま何時何分かを打つ |

**回した量を積み上げる。** 長い針の角度だけを見ると 12 をまたいだかが分からない
（右へ30分でも左へ30分でも文字盤の位置は同じ）。前回の角度との差を毎回たし込み、
通算の分として持つ。「30分すすめる」を「30分もどす」で通せないのはこのため。

**短い針も分に合わせて連続で動かす。** 10時40分の短い針は 10 をぴったり指しておらず、
10 と 11 の間の3分の2にある。ここが分かっていないと、12 をまたいだときに
時が変わったことに気づけない。

**5分きざみ。** 針の先を1分（6度）の精度で指で止めるのは無理がある
（分度器で角を5の倍数に限ったのと同じ判断 → 5.11）。
「5とびで読む」は2年で習うやり方でもあるので、文字盤の外がわに5とびの分を添える。

**4問の並びは固定：** またがずにすすめる → またいですすめる → またがずにもどす →
またいでもどす。またぐ問題だけを並べると「いつも時が1つ増える」で当てられる。

**拾う誤り。** 時をくり上げ忘れた形（10時40分の30分後を「10時10分」）と、
60をこえた分をそのまま言った形（「10時70分」）を、それぞれ名指しする。

### 5.20 がい数（四捨五入）

**要件。** 1セット4問。手は3つ。

| # | 手 | 何をするか |
|---|----|-----------|
| 1 | 見る位 | 四捨五入で見る位をタップする **← 本体** |
| 2 | 上げる・捨てる | その数字を見て切り上げか切り捨てかを決める |
| 3 | 書く | 答えを打つ |

**つまずきは計算ではない。**「百の位までのがい数に」と言われて百の位を
四捨五入してしまう——見るのはその1つ下、十の位のほう。
「までの位」と「見る位」がずれていることが言葉から読み取れていない。

そこで**位の名前を数字のすぐ下に置き、見る位を自分でタップさせる。**
ここを外したまま進むと切り上げ・切り捨ても答えも全部ずれるので、
この手を独立させると、どこで間違えたのかが分かれる。

**4問の並びは固定：** 位を指定・切り捨て → 位を指定・切り上げ（ちょうど5）→
上からのけた・切り捨て → 上からのけた・切り上げ。

- 切り上げと切り捨ては必ず両方入れる。片方だけだと「いつも上げる」で当たる
- **見る位がちょうど5になる問題を毎回1問入れる。**「5は上げる」は
  数の大小からは出てこない約束ごとなので、そこだけは出会わせておく
- 「上から◯けた」は位の名前が出てこないぶん難しいので後半に置く

**出題の制約。** のこす位より下がすべて0の数は使わない
（四捨五入しても数が変わらず、何をしたのか分からない問題になる）。

### 5.21 仮分数・帯分数

**要件。** 1セット4問。仮→帯、帯→仮 を交互に2問ずつ。手は向きごとに2つ。

| 向き | 手1 | 手2 |
|------|-----|-----|
| 仮分数 → 帯分数 | 1 が何こできるか | のこりは何こか |
| 帯分数 → 仮分数 | 整数を何こ分に直す | 合わせて何こか |

**手順そのものは軽い。図が本体。** 分子÷分母、整数×分母＋分子 を覚えるのは
難しくないが、その手順が何をしているのかが見えない。

1 を分母の数に分けた帯を並べ、分子のぶんだけ色をつける。
まるごと塗れた帯の本数がそのまま整数部分、残りが分数部分。
**仮分数→帯分数でも、帯分数→仮分数でも図はまったく同じ**にしてある。
向きがちがうだけで見ているものは1つだ、と分かるようにするため。

**出題の制約。**

- 分数部分は既約にする。1と2/4 のような形は教科書に出てこないし、
  仮分数にしたときの 6/4 も約分し残しになる（→ design-guidelines.md 1.4）
- 分母は 3〜6。2 は帯が粗すぎ、7以上は分けめが読めない
- 整数部分は 1〜2。帯が4本を超えると1本あたりが細くなって分けめが見えない
- **両方向を毎回通す。** 仮分数から帯分数にはできても逆はできない、
  ということが普通に起きるので、片方だけを続けない

**手を4種類に分けている**のは、どちらの向きでつまずいたのかを分けたいため。
1問で通るのは常に2つだけ。

### 5.13 追記：地図が小さくて押せない問題（2026-08）

**報告された不具合。** 北海道から沖縄までを1画面に入れると、
香川・大阪・東京は指では押せないうえ、そもそも見えない。
実測でも、スマホ幅（390px）での香川の当たり判定は **14px 四方**で、
一般に必要とされる 44px を大きく下回っていた。

**採った直し方。** 全国表示では、タップを「答える」ではなく
**「その地方に寄る」**にした。答えるのは寄ったあと。

- 地図をタップすると、押した場所の地方まで寄る（正確に押す必要がない）
- 地図の上に地方の帯を置き、そこからも寄れる
- 「日本ぜんたい」でいつでも戻れる
- 判定のあとは、正解の県の地方へ自動で寄せて大きく見せる
- 次の問題では日本ぜんたいに戻す（前の地方から探してしまうため）

これで香川の当たり判定は **53px 四方**になった（約3.8倍）。

手数は1回増えるが、日本 → 地方 → 県 という教わる順序とそろい、
「同じ地方だよ」「もっと北のほう」という返しが操作と噛み合う。

**採らなかった案。**

| 案 | 採らなかった理由 |
|----|-----------------|
| ピンチ／＋−でのズームとパン | 操作が増え、「探す」から意識がそれる。低学年には重い |
| 地方ごとに分割して並べる | **位置関係が壊れる。** 位置を覚えるためのアプリなので使えない |
| 当たり判定の丸をさらに大きくする | 隣の県と重なる。そもそも**見えないものは押せない** |

**あわせて**、地図だけカードの左右いっぱいまで広げた（せまい画面で幅 +32px）。

### 5.22 くり上がり・くり下がり（さくらんぼ計算）

**要件。** 1セット4問。たし算2問 → ひき算2問。手は向きごとに3つ。

| 向き | 手1 | 手2 | 手3 |
|------|-----|-----|-----|
| くり上がり（8+5） | あといくつで10 | のこりを分ける | 10とあわせる |
| くり下がり（13−8） | 10といくつに分ける | 10からひく | あわせる |

**このサイトでいちばん下の段。** 8+5 や 13−8 が出てこないままだと、
ひっ算・かけ算・わり算がすべて「1けたの計算で止まる」ことになる。

**つまずきは答えを覚えていないことではない。** 10のまとまりを作る手が
出てこないこと、そして**どちらの数を分けるのかで迷う**こと。
たし算は後ろの数、ひき算は前の数を分ける。ここが逆になる。

そこで**分ける数だけを式の中で枠で囲み**、そこからさくらんぼを下ろす。

**10のわく（5×2）を出す。**「あと2で10」は数だけ言われても1年生には出てこない。
点を置いて、空いている数がそのまま答えになるようにする。
教室でブロックを並べてやっていることと同じ。

**これは答えを見せているのではないか**、という点は検討したうえで残している。
この段階で練習させたいのは「10の補数を思い出すこと」ではなく
**「10のまとまりを作るという手を使うこと」**なので、
数えて確かめられる形にしておくほうがよい。
数えられているかどうかは、手ごとの記録に出る。

**出題の制約。** くり上がり・くり下がりが必ず起きる数だけを使う
（8+1 のような、分けなくても解ける問題は練習にならない）。
たし算とひき算を混ぜない。くり下がりは後で習うし、途中で向きが変わると
「どちらの数を分けるのか」が余計に混乱する。

**手を6つに分けている**のは、くり上がりはできるがくり下がりはできない、
が普通に起きるため。1問で通るのは常に3つ。

### 5.23 10のなかま（10の合成・分解）

**要件。** 1セット10問。1〜9 の 9つのなかまを、2つの向きで出す。

- 合成：「7 と いくつで 10？」（たし算のくり上がりで使う）
- 分解：「10 は 7 と いくつ？」（ひき算のくり下がりで使う）

**さくらんぼ計算（5.22）でいちばん止まる手を、単独で速く回すための単元。**
ここが出れば くり上がりは通るし、「10から8をひくと」も同じ知識で解ける。

**9つしかないことを、画面に出しておく。** 九九の81マスに対してこれだけなので
全部おぼえきれる。**終わりが見えること自体が、苦手な子には大きい。**
9つのなかまはいつも画面下に並べ、おぼえた順に色がつく。

**記録の単位は「見せた数」1〜9 の9つ。** 7と3 と 3と7 を同じ1組として
5組で数えることも考えたが、やめた。画面に9つ出しているのに数え方だけ
5組にすると食い違うし、「7といくつ」と「3といくつ」は思い出す向きがちがう。

**まちがえたときは、どちらへ動かせばよいかを言う。**
「7 と 5 で 12。10 を 2 こえているよ」「10 まで あと 2 たりないよ」。
「ちがうよ」だけでは、次に何をすればよいのか分からない。

### 5.24 かけ算の意味（1つ分の数 × いくつ分）

**要件。** 1セット4問。手は3つ。1つ分 → いくつ分 → ぜんぶで。

**九九は言えるのに文章題で式が立てられない**、を正面から扱う。
原因は計算力ではなく、かけ算が「1つ分の数」と「いくつ分」の
かけ合わせだと分かっていないこと。九九を先に覚えると、この意味が
抜けたまま先へ進めてしまう。

**答えを最後に置く。** 先に「ぜんぶでいくつ」を聞くと、絵を数えて
出せてしまい、かけ算を使わずに終わる。式は、子どもが埋めた2つの数から
組み立てて見せる。

**4問目に、入れかえた絵を並べて出す。** 「3こずつ5かご」と「5こずつ3かご」は
どちらも15だが、**絵はまったく別のものになる。**
ここが分かると、文章題でどちらの数が「1つ分」なのかを読み取れるようになる。

**出題の制約。**

- 1つ分といくつ分は**必ずちがう数**にする。同じ数だとどちらを聞かれても
  同じ答えになり、2つを区別する練習にならない
- 答えは九九の範囲（81まで）
- 場面は4問とも別のもの（さら・はこ・ふくろ・かご）
- 入れものによって動詞を変える。**さらには「のっています」、
  ふくろ・はこ・かごには「入っています」。** 共通にすると日本語がおかしくなる

**式の順序（3×4 か 4×3 か）は正誤の判定に使っていない。**
表示は教科書に合わせて「1つ分の数 × いくつ分」の順にしているが、
ここで問いたいのは順序ではなく、2つの数がそれぞれ何を表しているか。

### 5.25 面積と周りの長さ

**要件。** 1セット4問。前半2問は「なぞる → 数える」、後半2問は「形を変える」。

**面積と周りの長さを取りちがえる**のは、4年でいちばん多いつまずきのひとつ。
「たて×よこ」だったか「（たて＋よこ）×2」だったかを思い出せない、という形で出る。
式を覚え直させても、次の週にはまた入れかわる。

入れかわるのは、**2つが別の量だと分かっていない**から。どちらも
「長方形の大きさを表す数」に見えているので、どちらの式でも通りそうに感じる。

**そこで、やることを分ける。**

- まわりの長さ … **ふちを なぞる。** 4つの辺を順にタップすると長さがたされ、
  1しゅうして はじめて数が出る
- 面積 … **中の マスを 数える**（数字キーで打つ）

手の動きが別なので、式を思い出せなくても取りちがえようがない。
なぞる形にしたのは、**「たて＋よこ」で止まる**誤りをその場でつかまえるため。
2辺だけでボタンを押すと、なぞれていない辺が灰色のまま残る。
返す言葉は、足りない本数だけでなく**どの向きの辺が残っているか**まで見て変える
（たてとよこを1本ずつで止まった子と、よこ2本で止まった子は頭の中が別）。

**後半2問は、片方を止めて もう片方を 動かす。**

- まわりの長さを 20cm（または24cm）に止めて、面積をいちばん大きくする
- 面積を 12cm²（または16cm²）に止めて、まわりの長さをいちばん短くする

たてを1つ変えると、よこがいっしょに決まる。**操作は1つだけ**にしてあるので、
止めたほうが動かないことが確実に見える。
答えはどちらも「いちばん正方形に近い形」。

**できたら、選べた形をぜんぶ表にして出す。** 止めたほうの数を列に入れて、
同じ数がたてにならぶようにする。20cm が5回ならんだ横で面積が 9→25cm² と
変わるのが、**同じ周りの長さでも面積は同じにならない**をいちばん速く見せる。

**出題の制約。**

- 前半2問は組で作り置きする。**2問目は必ず「まわりは長いのに面積は小さい」**形にする。
  適当な長方形を2つ出してもこの関係になるとは限らず、
  いちばん見せたいことが出たり出なかったりする
- 面積の差は 4cm² 以上。1cm² しかちがわないと「ほとんど同じ」に見える
- どちらの長方形も、まわりの長さと面積が**同じ数にならない**ようにする
  （4×4 は まわり16cm・面積16cm² で、取りちがえていても気づけない）
- 形を変える問題は、**動かしはじめが答えになっていない**こと
- 方眼の枠は、形を変えても動かさない。枠も一緒に伸び縮みすると、
  どちらの向きに変わったのかが見えなくなる
