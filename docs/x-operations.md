# X（旧Twitter）運用方針

「わかる・できる」の認知拡大を目的とした、Xアカウントの運用方針。

最終更新: 2026年8月

---

## 1. 目的とKPI

### 1.1 目的

サイトの認知を広げ、**実際に使ってもらう**こと。

### 1.2 KPI

フォロワー数は目的ではなく手段である。優先順位をつけて次のように置く。

| 区分 | 指標 | 位置づけ |
|------|------|----------|
| 主KPI | サイトのセッション数、ドリル開始数 | 最終的に見たいのはこれ |
| 副KPI | Xからサイトへの流入数 | Xが機能しているかの判断 |
| 参考 | インプレッション、フォロワー数、エンゲージメント率 | 投稿の型を改善するための材料 |

**フォロワーが増えてもサイトに人が来ていなければ、運用は失敗している。**
この前提を月次の振り返りで毎回確認する。

> 注: 主KPIはサイト側の解析を導入するまで測定できない（→ 4章）。
> 当面はX標準のアナリティクスで取れる範囲で判断する。

## 2. 決定事項

| 項目 | 決定 |
|------|------|
| 運用形態 | **当面は手動運用**。API利用と自動化は行わない（→ 5章に保留） |
| 発信者の人格 | **作った本人として発信する**（サービス公式アカウントの体裁は取らない） |
| アカウント名 | わかる！できた！サイト |
| アカウントID | @WakaruDekita |
| 投稿頻度 | **週3回程度** |
| 解析ツール | **今回は導入見送り**。選定は今後検討する |
| 返信・DM | 自動化はしない。通知を人が確認し、必要なものに手で返す |

### 2.1 アカウント名についての補足

サイト名は「**わかる・できる**」、アカウント名は「**わかる！できた！サイト**」で、
表記が一致していない。「できた！」は達成感が伝わる良い表現だが、
**サイト名で検索した人がアカウントにたどり着けない**おそれがある。

対策として、**表示名または自己紹介に正式表記を含める**。具体案は 3.2 / 3.3 に置く。

### 2.2 発信者の人格

**現役の小学校教員であることは事実であり、これを前面に出す。**

保護者にとって、教える現場を知っている人が作ったという情報は、
機能の説明より遥かに信頼につながる。**このアカウント最大の資産**として扱う。

ただし肩書きだけを掲げても響かない。**肩書き＋具体的な観察**の形にすると効く。

> ×「現役教員が作った算数ドリルです」
> ○「通分でつまずく子を何人も見てきたので、そこを重点的に練習できるようにしました」

肩書きは信頼の担保として置き、実際に語る中身は現場で見てきた具体的な話にする。

#### 書くときの注意

- **児童・保護者・同僚の個人が特定されうる内容は書かない。** 具体例は一般化して書く
- 勤務校が特定される情報（校名、地域、行事の詳細など）を出さない
- 学校・教育委員会の方針に反しない範囲で運用する（勤務先のSNS規程を確認）
- **エピソードは必ず実体験に基づくものにする。** 作り話は書かない

### 2.3 トーン＆マナー（投稿の人格）

#### 目指す人格

**「教室で保護者や子どもに話しかけるときの自分」** を投稿の人格とする。

いわゆる「陽キャ」「コミュ強」を演じることは**推奨しない。** 理由は2つある。

1. **続かない。** 手動運用で最大の失敗要因は、書くのが負担になって止まることである。
   自分でない声で書き続けるのは消耗が大きく、数週間で息切れしやすい
2. **この読者層には逆効果になりうる。** テンションの高い文体は、保護者や教員から見ると
   広告や情報商材のアカウントに見えやすい。**このアカウントの武器は現役教員の観察であり、
   それを煽り気味の文体で語ると、かえって信頼が下がる**

必要なのは「明るいコミュ強」ではなく、**「感じのいい先生」** である。
暗くない・押しつけない・読み手を気にかけている、の3つが満たされていれば十分明るく読める。
これは内向的な人にも無理なく続けられる。

#### 具体的な設定

| 項目 | 設定 |
|------|------|
| 一人称 | わたし |
| 語尾 | です・ます。断定しすぎず「〜と思います」「〜かもしれません」も使う |
| テンション | 中。落ち着いているが、冷たくはない |
| 絵文字 | 0〜2個まで。使うなら文末に1つ程度 |
| 感嘆符 | 1投稿につき1つまで |
| 書き出し | 挨拶は省き、**具体的な話からいきなり始める** |
| 読み手への配慮 | 「〜な方はいませんか？」など、問いかけを1つ入れると温度が出る |

#### 使わない表現

- 煽り、危機感の押し売り（「知らないと損」「9割の親が間違えている」など）
- 強い断定（「絶対に」「必ず」）。教育の話では特に避ける
- 他者・他の教材への批判
- 子どもや保護者を下に見る表現、誤答をからかう表現
- 「バズ」を狙った過度な一般化

#### 言い換えの例

| 避ける | 置き換え |
|--------|----------|
| みなさんこんにちは！今日も投稿していきます！ | （挨拶は省いて、いきなり本題に入る） |
| これマジでヤバいです！！！ | これ、意外と大事なところです |
| 絶対にこうすべきです | わたしのクラスではこうしています |
| 9割の子ができていません | つまずく子が多い印象があります |
| 神ツールできました🔥🔥🔥 | 新しい単元を追加しました |

#### 投稿前のチェック

1. 感嘆符は1つ以内か
2. 断定しすぎていないか
3. 誰かを下に見ていないか
4. 個人が特定されうる情報が入っていないか
5. **自分が読み手だったら、この文を書いた人を信用するか**

## 3. 当面の運用（手動フェーズ）

### 3.1 プロフィールの記載事項

アカウントは開設済み。各欄に入れる内容を以下に定める。

| 欄 | 記入内容 | 上限 |
|----|----------|------|
| ユーザー名 | `@WakaruDekita` | 15字 |
| 名前 | → 3.2 | 50字 |
| 自己紹介 | → 3.3 | 160字 |
| ウェブサイト | `https://wakaru-dekita-site.com/` | 100字 |
| 場所 | **空欄を推奨**（→ 下記） | 30字 |
| 生年月日 | 非公開 | — |
| プロフィール画像 | 作成済みのアイコン（オレンジ地に白の「わ」） | — |
| ヘッダー画像 | 1500×500（未作成） | — |

**ウェブサイト欄にUTMパラメータは付けない。** 解析ツールを導入していない現状では
判別する手段がなく、URLの見た目が悪くなるだけになる。解析を導入する際に改めて付ける。

**場所欄は空欄を推奨する。** 現役教員として発信する以上、勤務地の推測につながる情報は
出さない方がよい。入れるとしても「日本」程度にとどめる。

### 3.2 名前（表示名）

サイト名「わかる・できる」で検索した人が辿り着けるよう、
**表示名のどこかに正式表記を含める。**

**推奨:**

```
わかる！できた！｜小学生の算数ドリル「わかる・できる」
```

**代替案:**

```
わかる！できた！｜現役小学校教員がつくる算数ドリル
```

```
わかる・できる｜小学生の無料算数ドリル
```

推奨案は正式名称を含むため検索で見つかりやすい。
代替案の1つ目は肩書きが名前の段階で目に入るが、サイト名が入らないため、
その場合は自己紹介の冒頭で正式名称を補う。

### 3.3 自己紹介（bio）

上限160字。以下はいずれも収まる（推奨案109字／短縮版85字）。

**推奨案:**

```
現役の小学校教員です。子どもがつまずくところを見てきて、
小学生向けの無料算数ドリル「わかる・できる」を作りました。
登録不要・完全無料・広告なし。1問10秒、4択でサクッと。
週3回、算数の1問や教え方のコツを投稿します。
```

構成の意図は次のとおり。

| 要素 | 役割 |
|------|------|
| 現役の小学校教員です | 信頼の担保。最初の一文に置く |
| 子どもがつまずくところを見てきて | 肩書きを具体に接続し、作った動機を示す |
| サイト名（正式表記） | 検索性の確保 |
| 登録不要・完全無料・広告なし | 保護者が気にする点を先回りして潰す |
| 週3回〜投稿します | **フォローする理由**。これがないと follow されにくい |

**短縮版**（文字数が収まらない場合）:

```
現役の小学校教員。子どものつまずきを見てきて、無料の算数ドリル
「わかる・できる」を作りました。登録不要・完全無料・広告なし。
週3回、算数の1問と教え方のコツを投稿します。
```

> 「広告なし」は現時点の事実だが、**書いた時点で約束になる。**
> 将来収益化を検討する際は、この記載の扱いも併せて判断すること（→ requirements.md 10.1）。

### 3.4 固定ポスト

投稿の文字数上限は280。**日本語1字＝2、半角1字＝1、URLは長さに関わらず一律23**で
カウントされるため、日本語だけなら実質130字程度が上限になる。以下はいずれも収まる。

**推奨案**（260/280）

```
小学校で教員をしています。

「わからない」まま進んでしまう子を減らしたくて、
無料の算数ドリルを作りました。

「わかる・できる」
・登録不要・完全無料
・1問10秒、4択でサクッと

いまは たし算・ひき算 と 九九。
次は分数（通分・約分）です。

wakaru-dekita-site.com
```

**簡潔版**（254/280）

```
小学校で教員をしています。
子どもがつまずくところを練習できる無料の算数ドリルを作りました。

「わかる・できる」
・登録不要・完全無料
・1問10秒、4択でサクッと
・スマホ／タブレット対応

いまは たし算・ひき算 と 九九。次は分数です。

wakaru-dekita-site.com
```

固定ポストは**プロフィールを見た人が最初に読む文章**になる。
サイトの説明だけでなく「誰が、なぜ作ったか」を必ず含める。

推奨案は「わからないまま進んでしまう子を減らしたい」という動機を置いている。
機能の羅列より、**なぜ作ったかの一文**の方が記憶に残り、共感で広がりやすい。

#### 最初のポストについて

**最初のポストは、投稿した時点では誰にも読まれない。** フォロワーが0だからである。
読まれるのは、後から誰かがプロフィールを訪れたときになる。

したがって、**最初のポスト＝固定ポスト**と考えて書き、作り込みすぎないこと。
完璧を目指して手が止まる方が損失が大きい。

以下は上の推奨案とは別の切り口の案。文字数はいずれも上限内（実測済み）。

**明るめのトーン**（272/280）

```
はじめまして！小学校で教員をしています。

「算数きらい」を「できた！」に変えたくて、
無料のドリルサイトを作りました。

「わかる・できる」
・登録不要・完全無料
・1問10秒、4択でサクッと

いまは たし算・ひき算 と 九九。
次は分数にとりかかっています。

wakaru-dekita-site.com
```

**エピソードから入る**（279/280。最も読まれやすいが、余白がないので推敲時は要注意）

```
「先生、分数ってなんで下をそろえるの？」

そう聞かれて、うまく答えられませんでした。
やり方は教えられても、意味を伝えるのは難しい。

つまずくところを何度でも練習できる場所がほしくて、
無料のドリルを作りました。

「わかる・できる」登録不要・完全無料です。

wakaru-dekita-site.com
```

> **エピソード案の一文目は、必ず自分の実体験に差し替えること。**
> 上の例は書き出しの「型」を示すためのものであり、実際にあった出来事ではない。
> 現場の具体的な一言は最も強い素材になるが、**作り話にすると資産が負債に変わる。**

### 3.5 投稿の型（週3回の回し方）

サイトの更新告知だけでは月1〜2回しか投稿できず、アカウントは伸びない。
**毎回のネタを考えなくて済むよう、型を決めて回す。**

| 型 | 頻度 | 内容 | リンク |
|----|------|------|--------|
| **A. 今日の1問** | 週1 | 算数の問題を1問出す。「答えは何でしょう？」 | なし |
| **B. つまずき解説** | 週1 | 通分・約分など、つまずく箇所の考え方や教え方のコツ | なし |
| **C. 制作の裏側／更新報告** | 週1 | 何を作っているか、なぜそう作ったか。新単元の公開時はここで告知 | 告知時のみあり |

**リンクは原則入れない。** Xは外部リンクを含む投稿の表示を抑える傾向があるため、
リンクなしの方が多くの人に届く。導線はプロフィール欄に集約する。
（将来API経由に移行した場合は、リンクの有無でコストが13倍変わるため、この原則がさらに効く → 5.2）

#### 型ごとの例

**A. 今日の1問**

```
【今日の1問】

7 + 5 = ?

低学年のうちは「10のかたまり」を作れると速くなります。
7に3を足して10、残り2で12。

答えられたお子さんはえらい！
```

**B. つまずき解説**

```
分数でつまずく子の多くは、計算そのものより「通分」でつまずきます。

1/2 + 1/3 を「2/5」としてしまうのは、
分母の意味（いくつに分けたか）が抜けているサイン。

ピザを2等分と3等分で比べて見せると、
「同じ大きさに揃えないと足せない」が腹落ちしやすいです。
```

**C. 制作の裏側**

```
ドリルの選択肢を作るとき、わざと「正解に近い数」を混ぜています。

7+5 の選択肢が 12・50・3・99 だと、
計算しなくても正解が分かってしまうので。

11・12・13・14 のように迷う並びにすることで、
ちゃんと計算しないと解けないようにしています。
```

### 3.6 返信・DMの扱い

- **自動化はしない。** 誤爆のリスクが高い
- **ただし対応はする。** Xアプリからの返信・DMは無料であり、
  質問や感想を無視し続けるアカウントは認知拡大の面でマイナスになる
- **週1回程度、通知を確認して必要なものに手で返す**
- 当面はこれがサイトのフィードバック窓口も兼ねる

## 4. 計測（当面の制約）

### 4.1 いま測れるもの・測れないもの

サイト側の解析は**導入を見送った**ため、測定範囲に制約がある。

| 測れる（X標準のアナリティクス） | 測れない |
|--------------------------------|----------|
| インプレッション、エンゲージメント | サイトのセッション数 |
| フォロワーの増減 | ドリルを実際に解いた人数 |
| プロフィールクリック数 | 再訪率、滞在時間 |
| リンククリック数（リンク付き投稿のみ） | どの単元が使われているか |

つまり当面は「**Xでどれだけ反応があったか**」までは分かるが、
「**サイトに来た人が実際に使ったか**」は分からない。

主KPIをサイトのセッション数に置いている以上、これは本質的な制約である。
運用を続けて手応えが出てきた段階で、解析の導入を再検討することを推奨する。

### 4.2 月次の振り返り

X標準のアナリティクス画面（無料）から次を確認し、記録する。

- インプレッション、エンゲージメント率、フォロワー増減
- 反応が良かった投稿・悪かった投稿と、その要因の仮説
- 翌月に試すこと

型A・B・Cのどれが伸びているかを見て、配分を調整する。

## 5. 将来の自動化（保留中）

当面は手動運用のため、以下は着手しない。再検討する際の判断材料として残す。

### 5.1 X APIの料金体系（2026年8月時点）

**無料枠は新規開発者には提供されていない。** 従来のFree/Basic/Proという月額制は
新規受付を終了し、**従量課金（pay-per-use）が既定**になった。

| 操作 | 単価 |
|------|------|
| ポスト作成（テキスト・画像、**URLなし**） | $0.015 / 回 |
| ポスト作成（**URLを含む**） | **$0.20 / 回** |
| ポストの読み取り | $0.005 / 件 |
| ユーザー情報の読み取り | $0.010 / 件 |

出典: [X API公式ドキュメント](https://docs.x.com/x-api/getting-started/pricing) /
[発表スレッド](https://devcommunity.x.com/t/announcing-the-launch-of-x-api-pay-per-use-pricing/256476)

> 単価は変動しうるため、着手時に必ず公式ドキュメントで再確認すること。

### 5.2 設計原則

**URLを含むポストは、含まないポストの約13倍のコストがかかる。**
自動化する場合も、3.5 と同じく「日常投稿にリンクを入れない」原則を維持する。
コスト最適と到達最適が一致している。

### 5.3 想定コスト

週3回投稿・リンクなしを基本とした場合、**月$0.2程度**にしかならない。
毎日投稿に増やしても月$0.5程度。**費用は自動化を見送る理由にはならない。**

見送りの理由は費用ではなく、**まず手で運用して感触を掴むため**である。

### 5.4 Claudeの役割（自動化する場合）

| できる | できない |
|--------|----------|
| 自動投稿の仕組み（GitHub Actions）を実装する | 常時稼働してアカウントを見張る |
| 投稿文のテンプレートや文面を作る | セッション終了後に自律的に動く |
| 問題画像を生成する仕組みを作る | この開発環境から外部APIを呼ぶ（ネットワーク制限） |
| 蓄積した指標を分析し、月次レポートを書く | 判断が要る対応（炎上時など）を代行する |

自動投稿の実体は**GitHub Actionsのスケジュール実行**であり、Claudeのセッションではない。
月次分析については、スケジュール実行（Routine）で毎月セッションを起動する形が取れる。

### 5.5 自動化する場合の順序

1. 告知の自動化（頻度が低く、失敗しても影響が小さい。仕組みの検証に適する）
2. 定期投稿の自動化（既存の出題エンジンと画像生成の仕組みを流用できる）
3. 指標収集と月次レポートの自動化

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| 勤務校・児童が特定される | 具体例は一般化して書く。校名・地域を出さない（→ 2.2） |
| 勤務先のSNS規程に抵触する | 発信前に規程を確認する（→ 2.2） |
| 投稿が続かない | 型を決めて回す（→ 3.5）。ネタを毎回考えない |
| 同一内容の連投による規約違反 | 過去の投稿を確認し、文面に変化をつける |
| 子ども向けサービスとしての体裁 | 過度に煽らない。誤答を笑うような文面にしない |
| 誤った内容の投稿 | 問題と答えの整合性を投稿前に確認する |
